# LangPlant CRM

CRM для производства коротких роликов LangPlant по трёхстороннему договору:
ролики и их материалы, языковые версии, публикации по площадкам, ежедневный план,
архив материалов, библиотека музыки. Работает одинаково удобно с телефона и с компьютера.

Четыре учётки создаются при первом запуске: **Саша** (администратор), **Ксения**, **Анастасия**, **Изабелла**.

## Что умеет

**Ролики**
- Список с фильтрами (этап, статус публикации, теги, язык, исполнитель, поиск) и канбан-доска по этапам с перетаскиванием (на телефоне долгое нажатие).
- Карточка ролика: этап, ответственный, дата публикации, теги, чек-лист, сценарий, заметки, обсуждение, история изменений.
- Код ролика `LP-0042` присваивается автоматически и не меняется.
- Флаг «новый уникальный ролик». Перезалив, смена обложки или субтитров новым роликом не считаются (п.6.3).

**Материалы и языковые версии**
- У каждого ролика есть языковые версии (RU, EN, …). У каждой версии своя озвучка, субтитры, финальный монтаж, обложка, описание для публикации и свои публикации.
- Слоты файлов для каждой языковой версии: финальный ролик, чистый голос, субтитры, обложка, сценарий.
- Общие слоты для всех языков: дорожка без голоса, видео без субтитров, музыка, SFX, исходники, проект монтажа, графика, прочее.
- Типы файлов настраиваются: можно добавлять свои и отмечать обязательные.
- Перетаскивание файлов в окно. Тип и язык угадываются по имени файла, перед загрузкой их можно поправить.
- Версии файлов: новая загрузка в тот же слот становится v2, предыдущие версии сохраняются.
- Просмотр видео (лёгкое превью или оригинал), аудио и картинок. Скачивание отдельных файлов и всего ролика одним zip.
- Для каждого файла видно, где он сейчас: «на сервере», то есть ещё не перенесён, или «на компе».

**Договорные метрики (нейтрально, без слова «нарушение»)**
- План «1 новый уникальный ролик в день» (п.6.1). TikTok, Shorts и Reels одного ролика считаются как один ролик (п.6.2). Какие площадки засчитываются в план, задаётся в настройках.
- Полоса дней, серия, резерв готовых роликов (п.6.9), до какого дня покрыт план, пропуски за 30 дней и подряд (п.26.3).
- Уважительная причина дня: болезнь, площадка недоступна, блокировка, форс-мажор (п.6.6–6.8, 31). Такой день не считается пропуском.
- Архив (п.7): контроль минимального набора материалов (финал, чистый голос, дорожка без голоса) и таймер 48 часов после первой публикации (п.7.6).
- Озвучка языковой версии: оригинал, дубляж, ИИ-голос. Для ИИ-голоса показывается предупреждение про п.16.4.

**Публикации и календарь**
- Площадки (TikTok, YouTube Shorts, Instagram Reels и любые свои) и аккаунты, в том числе отдельные аккаунты под каждый язык.
- Статусы публикации: в плане, отложена в соцсети, опубликовано, не публикуем, снято. Плюс дата и время, ссылка, просмотры, заметка.
- Календарь на месяц с переносом роликов перетаскиванием. На телефоне календарь показывается лентой по дням.
- После первой публикации ролик автоматически переходит на этап «Опубликован».

**Музыка**
- Загрузка пачкой MP3. Название, исполнитель, BPM, жанр и обложка берутся из ID3-тегов, в том числе в кодировке cp1251.
- Теги по группам: жанр, настроение, темп, назначение — в карточке трека все группы видны сразу. Фильтры: внутри группы срабатывает любой выбранный тег, между группами нужны все условия сразу.
- Волна трека по громкости (видно вступление, куплеты, дропы и паузы), плеер внизу экрана: перемотка кликом или перетаскиванием по волне, на телефоне — по полоске плеера и в развёрнутом плеере. Играет при переходах между страницами, управляется с экрана блокировки телефона. Избранное.
- Источник, лицензия, ссылка на лицензию, площадки, где трек можно использовать (п.14.3–14.4). Список роликов, в которых трек использован.
- Массовое редактирование: теги, источник и лицензия, удаление.

**Прочее**
- Корзина: удалённое можно восстановить. Удалить навсегда может только администратор (п.17.5).
- Обновления приходят без перезагрузки страницы: что поменял один участник, сразу видят остальные.
- Справочники настраиваются: этапы, площадки, аккаунты, языки, типы файлов, шаблон чек-листа, теги, параметры плана.
- Аватарки: каждый ставит своё фото в профиле (администратор может поставить любому).
- PWA: сайт можно добавить на экран «Домой». Светлая и тёмная тема.

## Архитектура

```
 телефон / ноутбук                 VPS (мало места)                     комп Саши (диски)
┌──────────────────┐  HTTPS   ┌────────────────────────────┐   WSS    ┌─────────────────────────┐
│  веб-приложение  │ ───────► │ crm-server (Go, ~20 МБ RAM)│ ◄─────── │ crm-node (Go + ffmpeg)  │
│  React, PWA      │          │ • API + интерфейс          │  нода    │ • основной архив файлов │
│                  │ загрузка │ • SQLite с метаданными     │  сама    │   (по sha256)           │
│                  │ частями  │ • буфер загрузок (лимит)   │ звонит   │ • превью, обложки,      │
│                  │ с докач- │ • LRU-кэш и превью         │ на VPS   │   волны (ffmpeg)        │
│                  │ кой      │ • хаб связи с нодой        │          │ • бэкапы базы с VPS     │
└──────────────────┘          └────────────────────────────┘          └─────────────────────────┘
```

- **Загрузка.** Браузер грузит файл на VPS частями по 8 МБ. Если связь оборвалась, загрузка продолжается с того же места. Сервер сразу считает sha256.
- **Перенос на комп.** VPS сообщает ноде о новом файле, нода скачивает его (с докачкой), проверяет хэш и подтверждает. После этого копия на VPS становится просто кэшем, который вытесняется по LRU. Пока нода не подтвердила файл, он лежит в буфере и не удаляется.
- **Просмотр и скачивание.** Если копии на VPS нет, сервер просит ноду прислать нужный диапазон байтов, и нода передаёт их по отдельному исходящему WebSocket. Range-запросы поддерживаются, поэтому видео можно перематывать. Небольшие файлы после просмотра остаются в кэше VPS.
- **Тяжёлая работа на компе.** Нода делает обложки, превью 960p H.264, метаданные и волны. VPS хранит только маленькие производные файлы.
- **Нода всегда звонит сама.** Входящие порты, туннели и белый IP не нужны: обычный WSS на 443-м порту выглядит как HTTPS.
- **Бэкап базы.** Нода раз в 6 часов забирает снимок базы. Команда `crm-node export` собирает из бэкапа и файлов обычную структуру папок `Ролики/LP-0042 Название/ru/Финальный ролик/…`.

Подробно: [docs/DEPLOY.md](docs/DEPLOY.md) (развёртывание) и [docs/PROTOCOL.md](docs/PROTOCOL.md) (протокол VPS ↔ нода).

## Структура

```
cmd/crm-server      точка входа сервера (+ CLI: passwd, useradd, users)
cmd/crm-node        точка входа ноды (+ CLI: export, verify)
internal/server     API, авторизация, буфер и кэш, хаб ноды, план публикаций
internal/node       нода: синхронизация, раздача, ffmpeg, бэкапы, экспорт
internal/proto      сообщения протокола VPS ↔ нода
internal/db         SQLite и миграции
internal/webui      встроенная сборка веб-интерфейса
web/                React + TypeScript + Vite
deploy/server       Dockerfile, compose, Caddy/nginx, systemd для VPS
deploy/node         Dockerfile и compose для компа
docs/               развёртывание и протокол
```

## Локальный запуск

Нужны Go 1.26+, Node 22+, ffmpeg.

```bash
make build                                   # интерфейс + bin/crm-server + bin/crm-node
CRM_NODE_TOKEN=dev-token-dev-token-dev-token ./bin/crm-server          # http://localhost:8080
NODE_SERVER_URL=http://localhost:8080 NODE_TOKEN=dev-token-dev-token-dev-token ./bin/crm-node
cat data/initial-passwords.txt               # пароли четырёх учёток
```

Интерфейс с горячей перезагрузкой: `cd web && npm run dev`, затем открыть http://localhost:5173 (API проксируется на :8080).

Тесты: `make test`. Сквозной тест поднимает сервер и ноду и проверяет загрузку частями, перенос на ноду, превью через ffmpeg, Range-раздачу через ноду, zip, кэш, план публикаций, бэкап, экспорт и удаление.
Проверка типов в интерфейсе: `cd web && npm run check`.
